# Mini NPU Simulator

외부 라이브러리 없이 Python 반복문만으로 MAC(Multiply-Accumulate) 연산을 구현하고, Cross(십자가)와 X 패턴을 판별하는 콘솔 애플리케이션입니다.

3×3 데이터를 직접 입력하는 모드와 `data.json`의 5×5, 13×13, 25×25 데이터를 일괄 분석하는 모드를 제공합니다. 각 패턴의 점수와 판정 결과를 출력하고, 크기별 평균 연산 시간을 측정해 입력 크기와 연산량의 관계를 확인할 수 있습니다.

> 📘 과제의 전체 배경과 요구사항은 [미션 가이드](mission/README.md)에서 확인할 수 있습니다.

## 주요 기능

- 3×3 필터 2개와 패턴을 콘솔에서 직접 입력
- 행·열 개수 및 숫자 형식 검증 후 잘못된 행 재입력
- `data.json`의 필터와 패턴 스키마 및 크기 검증
- `+`, `cross`, `x` 라벨을 `Cross`, `X`로 정규화
- 반복문으로 위치별 곱셈과 누적 합산(MAC) 수행
- `epsilon = 1e-9` 기준으로 부동소수점 동점 처리
- 케이스별 `PASS`/`FAIL` 및 실패 사유 출력
- 3×3, 5×5, 13×13, 25×25 연산 성능 측정
- 전체 테스트 수, 통과 수, 실패 수 요약

## 동작 원리

MAC 연산은 패턴과 필터에서 같은 위치의 값을 곱한 뒤 모두 더합니다.

```text
score = Σ(pattern[row][column] × filter[row][column])
```

Cross 필터 점수가 더 높으면 `Cross`, X 필터 점수가 더 높으면 `X`로 판정합니다. 두 점수의 차이가 `1e-9`보다 작으면 부동소수점 오차로 인한 잘못된 우열 판정을 막기 위해 `UNDECIDED`로 처리합니다.

```bash
git clone https://github.com/dlckdwls76/CodysseyMission_E1_3.git

```

환경에 따라 `python` 대신 `python3` 또는 Windows의 `py` 명령을 사용할 수 있습니다.

프로그램이 시작되면 실행할 모드를 선택합니다.

```text
=== Mini NPU Simulator ===

[모드 선택]

1. 사용자 입력 (3×3)
2. data.json 분석
선택:
```

### 모드 1: 사용자 입력

필터 A, 필터 B, 패턴을 각각 세 줄씩 입력합니다. 각 줄에는 공백으로 구분한 숫자 3개가 필요합니다.

```text
필터 A
0 1 0
1 1 1
0 1 0

필터 B
1 0 1
0 1 0
1 0 1

패턴
1 0 1
0 1 0
1 0 1
```

위 예시에서는 A 점수 `1.0`, B 점수 `5.0`이 계산되어 결과가 `B`로 판정됩니다. 점수와 함께 10회 반복 측정한 평균 연산 시간도 출력됩니다.

### 모드 2: data.json 분석

프로젝트에 포함된 `data.json`을 읽어 다음 순서로 처리합니다.

1. 크기별 Cross/X 필터 로드 및 검증
2. 패턴 키에서 크기 추출
3. 패턴과 필터의 크기 및 데이터 형식 검증
4. Cross/X MAC 점수 계산과 결과 판정
5. 예상 라벨과 비교하여 `PASS` 또는 `FAIL` 출력
6. 크기별 성능 표와 전체 결과 요약 출력

한 케이스의 데이터가 잘못되어도 전체 프로그램은 중단되지 않으며, 해당 케이스만 실패 처리하고 원인을 표시합니다.

## 결과 리포트

예제 `data.json`에는 5×5, 13×13, 25×25 크기의 Cross/X 패턴 총 6개가 포함되어 있습니다. 현재 자동 테스트에서는 6개 케이스가 모두 통과했으며 실패 케이스는 없습니다.

실패가 0개인 첫 번째 이유는 외부 데이터의 `+`와 `cross`를 모두 표준 라벨 `Cross`로 변환하고, 대소문자와 관계없이 `x`를 `X`로 변환하기 때문입니다.

두 번째 이유는 필터 키와 `expected` 값을 같은 표준 라벨로 정규화한 뒤 비교하므로, 표현 방식만 다른 라벨이 잘못된 실패를 만들지 않기 때문입니다.

세 번째 이유는 필터와 패턴을 사용하기 전에 행 수, 열 수, 숫자 여부를 검사하여 잘못된 입력이 MAC 연산에 전달되지 않기 때문입니다.

네 번째 이유는 각 패턴 키의 `size_N_idx`에서 `N`을 추출하고 동일한 크기의 `size_N` 필터를 선택하기 때문입니다.

다섯 번째 이유는 두 점수의 차이가 `1e-9`보다 작을 때 `UNDECIDED`로 처리하여 미세한 부동소수점 오차를 실제 점수 차이로 오해하지 않기 때문입니다.

실패가 발생한다면 원인은 크게 데이터·스키마 문제, 판정 로직 문제, 수치 비교 문제로 나누어 진단할 수 있습니다.

데이터·스키마 문제에는 누락된 `input`/`expected`, 잘못된 키 형식, 숫자가 아닌 원소, 필터와 패턴의 크기 불일치가 포함됩니다.

판정 로직 문제는 올바른 크기의 필터를 선택했는지, MAC 반복문이 모든 `N²` 위치를 정확히 한 번씩 계산했는지 확인하여 진단합니다.

수치 비교 문제는 두 점수가 매우 가까울 때 단순 `==` 또는 `>` 비교를 사용했는지 확인하고, epsilon 정책을 적용해 개선할 수 있습니다.

N×N 패턴 한 개의 MAC 점수를 계산하려면 모든 원소를 방문해야 하므로 곱셈은 `N²`회, 누적 덧셈도 `N²`회 수행됩니다.

따라서 MAC 함수의 시간 복잡도는 `O(N²)`이고, 추가 배열을 만들지 않고 점수만 누적하므로 추가 공간 복잡도는 `O(1)`입니다.

예를 들어 3×3은 9개, 5×5는 25개, 13×13은 169개, 25×25는 625개의 위치를 처리합니다.

입력 한 변의 길이가 커질수록 연산 횟수가 제곱으로 증가하므로 평균 실행 시간도 대체로 증가합니다. 단, 매우 짧은 실행 시간은 운영체제 스케줄링과 측정 오차의 영향을 받을 수 있어 프로그램은 각 크기를 최소 10회 반복 측정한 평균값을 출력합니다.

## 데이터 형식

`data.json`은 다음 구조를 사용합니다.

```json
{
  "filters": {
    "size_5": {
      "cross": [[0, 0, 1, 0, 0]],
      "x": [[1, 0, 0, 0, 1]]
    }
  },
  "patterns": {
    "size_5_1": {
      "input": [[1, 0, 0, 0, 1]],
      "expected": "x"
    }
  }
}
```

위 배열은 형식을 간단히 보여주기 위해 일부 행만 표시한 예시입니다. 실제 필터와 패턴은 반드시 `N×N` 크기여야 합니다.
